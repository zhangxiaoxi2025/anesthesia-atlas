## 初审问题与修复历史

### S01 — [P1] 固定靶区轮廓实际与神经和血管相交，不能声称它表示神经外、血管外空间

位置：`src/components/AnatomyViewer.jsx` 的 `perivascular` / `mcTarget`（审查快照第 72–81 行），与 `clinical.targets[].caution` 的“神经外、血管外邻近空间”表述。

候选实现将血管周围环固定在 `[-0.164, 1.30, -0.020]`，半径 13mm、管半径 1.3mm。独立使用交付源网格与相同 Y=1.30 平面求交，得到表面截点到环中心的径向范围：正中神经 12.606–14.589mm、尺神经 10.190–12.254mm、肱静脉 8.733–15.279mm。环管覆盖 11.7–14.3mm，因此与这些结构表面相交。桡神经在 25.603–27.739mm，反在环外。肌皮神经环中心 `[-0.183,1.30,-0.011]`，半径 6mm/管半径 0.7mm，也接触正中神经截线（最接近环中心约 6.435mm）。

这不是要求做扩散模拟。问题在于一个未经组织分割验证的产品几何，被文字赋予了“神经外血管外空间”的含义。轮廓替代实心球能减弱体积误解，但不能让位置本身得到验证。

建议：首版移除实体靶区圈，采用四神经/血管的选中高亮和文字解释；或将其改为明确的“关系标记/注意区域”，去掉神经外血管外、注药间隙、安全位置的承诺。没有来源筋膜与空间模型时，不把任意固定圈当作已验证注药区域。

状态：已修复并通过最终静态复核，见上方 S01 闭环记录。

### S02 — [P2] 横断面把 X 与 Z 按不同尺度绘制，局部关系在屏幕上横向拉宽

位置：`src/components/CrossSection.jsx` 的 `toScreen`（审查快照第 4–5 行）。

X 方向比例为 `290/0.19 = 1526.3 px/m`，Z 方向为 `210/0.20 = 1050 px/m`，相差约 1.45 倍。截线来自实际网格这一点成立，但圆形/相对间隔会被非等比例变换。对于解释神经—血管局部关系的模型切面，宜保持同一毫米比例。

建议：X/Z 使用同一比例并将窗口居中，必要时以留白适应宽高。主线程已明确接受并正在修复。

状态：已修复并通过最终静态复核，见上方 S02 闭环记录。

### S03 — [P2] 固定“肱血管”说明不能覆盖整个可拖动切面范围

位置：`src/components/CrossSection.jsx` 底部 micro-note（审查快照第 31 行）。

默认附近 Y=1.295/1.30 截到来源命名的肱动静脉，现有说明对这一默认层面正确。但滑杆允许到 Y=1.39，实际 `axillary-artery` 有 25 条截线，`brachial-artery`、`brachial-vein` 均为 0；此时仍显示“此上臂层面显示肱血管”会错误命名当前图。Y=1.32 还存在肱静脉段无截线的情况，不能把所有层面笼统描述成同一对血管。

建议：依据实际 `cuts` 列出相交血管名称，或将固定说明改为“血管名称随来源分段与层面变化”，并给实际血管截线可读取的标签/图例。投屏教学不应只依靠 SVG `<title>` 的鼠标悬停。

状态：已修复并通过最终静态复核，见上方 S03 闭环记录。

### S04 — [P2] 运动模式将同一前臂肌群轮廓同时投到掌面和背面

位置：`src/components/CoverageMap.jsx` 的 `MUSCLES` 与第 42 行渲染选择。

除桡神经前面和肌皮神经背面被清空外，正中神经、尺神经的同一组多边形在两个视图均被绘制。这样在标为背面的前臂上仍显示正中屈肌代表块，可能被读作后侧伸肌群由正中神经支配。底部“并非精确肌肉轮廓”说明解决了形状精度，却未解决前后肌群位置的含义。

建议：运动数据与感觉数据一样按 `front/back` 分组；正中前臂屈肌/旋前联系留在前面，桡神经伸肌留在后面，尺神经的前臂与手内肌分别表达，或用带动作名称的非位置示意图。不要用和皮肤感觉地图同样的无标签色块表达肌群。

状态：已按前/后侧独立数据修复并通过最终静态复核，见上方 S04；精细肌肉轮廓仍不作为本版承诺。

### S05 — [P2] 界面“模型来源”尚缺直接到实际固定资产及许可的入口

位置：`src/App.jsx` 的 `models` modal（审查快照第 151 行）。

本地 manifest 和归属文件记录充分，但弹窗链接只到通用 `Z-Anatomy/Models-of-human-anatomy`，实际所取资产来自 `LluisV/Z-Anatomy@6c7f9016...`。弹窗没有显示 CC BY-SA 4.0 或指向 `/models/ATTRIBUTION.md`、固定 FBX 来源、许可文件的入口。教学使用者难以从界面核对实际导入版本及再使用条件。

建议：直接显示固定导入仓库/短提交、CC BY-SA 4.0，与可点击的本地归属/许可；human-atlas 与骨创图谱继续作为交互/组织参考独立列出。不要把 UI 原创代码与资产写成同一种许可。

状态：已修复并通过最终静态复核，见上方 S05 闭环记录。

### S06 — [P1] 神经归类按 ID 前缀把桡动脉与尺动脉误归为神经

位置：`src/model-utils.js` 的 `nerveIdFor`（初始审查第 4–6 行），影响三维/横断面着色、点击选中、孤立观察与神经标签锚点。

函数把 `structure.id` 中 `radial-` / `ulnar-` 前缀直接映射成相应神经，没有先检查 `kind`。用实际交付 manifest 调用发现：`radial-artery`（桡动脉，kind=artery）返回 `radial`；`ulnar-artery` 返回 `ulnar`；对这两个实际对象执行 `structureVisible(..., isolated=true, selected=对应神经)` 均返回 true。因而“单独观察所选神经”会带上动脉，正常全上肢视图也会把它们赋予神经颜色与神经点击行为。

建议：`nerveIdFor` 首先拒绝非 `nerve` 类别，再处理主干或明确父神经关联；对实际 47 结构验证“只有 kind=nerve 能取得神经 ID”，特别覆盖两条动脉、真实 `radial-superficial` / `radial-deep`、`musculocutaneous-lateral-antebrachial-cutaneous` 与四主干。孤立神经场景的测试应确认没有 artery/vein/muscle/bone/skin。

状态：已修复并通过实际 47 结构的独立复核，见上方 S06 闭环记录。

## 已核实的规格符合项

- manifest 的 47 个 active structures 均来自同一个固定 Z-Anatomy 提交；四神经 ID 与先前独立 HTTP Range 核查到的 FBX 对象相符。没有把 human-atlas 的神经系统标签误当缺失四神经的几何。
- 导入脚本明确应用源 `matrixWorld` 后统一乘 0.01，没有跨源拟合或给神经补画曲线；元数据记录原对象 ID、来源、变换、文件散列与边界。
- 源模型中立位、肌皮神经近端有限、外/内侧束独立网格未确认、筋膜与可注射间隙未验证均有记录；没有把这些缺口填成虚假的源解剖。
- `intersectGeometry` 从三角形与平面实际求交，切面不是预绘固定图或灰度伪超声。多个层面实际截线数量不同；Y=1.295 与 1.30 都能截到四主干，Y=1.32 后肌皮主干不再相交，符合其源网格范围而非程序随意隐藏。
- 侧栏四神经选择、三维神经拾取、图层、透明度、孤立观察、相机预设、复位、真实切面滑杆、感觉/运动选项、教学步骤、六题识别练习、来源/边界说明均有具体实现。
- clinical JSON 把外周神经皮区、运动联系、根源、深部组织/关节麻醉范围区别开；把肋间臂神经、腋神经和内侧皮神经作为覆盖边界，而非自动并入四神经覆盖。
- 感觉 SVG 明确是原创典型支配示意，不从网格推断个体麻醉。它不保证精确边界和临床阻滞成功。
- 临床资料记录了来源实际可读范围、公开正文与检索摘录的区别，没有把未读全文声称为全文审阅。最终仍保留 `awaiting_clinician_review`，这不阻止本地学习原型的软件验收。

## 撤回的初步疑问

最初仅看 JSX 时疑似滑杆“近端/远端”反向。随后读取样式确认 `direction: rtl`，原画面左端实际对应较大 Y/近端，因此**不列为已证实缺陷**。主线程计划改成 LTR 加显式左远端/右近端，可降低维护与验证复杂度。
